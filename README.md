# AI 안전 용어집

AI 안전 동향 코퍼스에서 용어집으로 만들 값어치가 있는 표제어 **100개**를 뽑아
실제 용례와 수집 지표를 붙여 보여 준다. 독자는 비전문가, 표제어는 **개념어만**
— 기관·법령·모델명 같은 고유명사는 별도 부록 대상이다.

- **공개 사이트:** https://songkyungho.github.io/ai-safety-glossary/
- **소개:** https://songkyungho.github.io/ai-safety-glossary/about.html

같은 시리즈: [AI 안전 동향](https://songkyungho.github.io/ai-safety-digest/) ·
[AI 안전 라이브러리](https://songkyungho.github.io/ai-safety-library/)

## 빠른 사용

```bash
./run_build.sh          # 전체 재빌드 (후보 추출 → 표제어 → 지표 → 용례 → 사이트)
```

개별 단계:

```bash
python3 scripts/extract_candidates.py   # 1) 후보 추출  -> data/glossary_candidates.csv
python3 scripts/select_top100.py        # 2) 표제어 확정 -> data/glossary_top100.csv
python3 scripts/gloss_and_hubs.py       # 3) 병기율·허브 -> data/glossary_top100_hubs.csv
                                        #                 glossary_top100.md
                                        #                 glossary_watchlist.md
python3 scripts/build_json.py           # 4) 정의문 병합 + 용례 수집 -> data/glossary.json
python3 scripts/build_site.py           # 5) 정적 사이트 -> docs/
python3 scripts/centrality.py           # (참고) 실패한 중심성 지표 재현용
```

## 원천 데이터

코퍼스(`knowledge/digest.db`)와 토픽 분류(`topic_keywords.py`)는 **동향 Digest
저장소**가 갖고 있다. 복제하지 않고 참조한다 — 매일 갱신되는 쪽이 진본이어야
하므로. 기본 위치는 형제 폴더 `../AI Safety` 이고,
`GLOSSARY_DIGEST_REPO` 로 덮어쓸 수 있다 (`scripts/config.py`).

화면: [`docs/index.html`](docs/index.html)

**1) `extract_candidates.py`** — 동향 코퍼스 `digest.db`의 제목+요약 5,765건에서
한글 1~2gram·영문 1~3gram을 긁어 1만여 개 후보를 만든다(df≥5). 각 후보에:

| 지표 | 뜻 | 왜 |
|---|---|---|
| `df` | 등장 **문서 수** | 원시 빈도는 한 사안이 20개 언론에 실리면 20배로 부푼다 |
| `months` | 등장한 서로 다른 달 수 | 반짝 용어를 걸러내는 축 |
| `recency` | 최근 12개월 df ÷ 전체 df | 신생 용어 가점 |

점수 = `log1p(df) × log1p(months) × (1 + 0.8×recency)`.
토픽은 동향 저장소 `topic_keywords.py`의 17개 분류를 재사용해 자동 부여한다.

**2) `select_top100.py`** — 표제어 선정은 의미 판단(사람)이고, `df`/`months`/
`recency`는 코퍼스에서 자동 결합한다(전사 오류 방지). 변이 표기는
`variants`에 **구체어 우선**으로 적고 첫 일치를 대표로 쓴다.

## 설계 판단 세 가지

- **토픽 쿼터를 둔다.** 점수 순으로 100개를 자르면 보도량이 많은 법제·정치
  용어가 과반을 먹고 평가·정렬 기술 용어가 밀린다. 13개 버킷에 쿼터를 배분했다.
- **변이 df를 합산하지 않는다.** `정렬`(260)과 `alignment`(197)를 더하면 같은
  문서를 두 번 센다. 대표 표기 하나의 df만 헤드라인 숫자로 쓴다.
- **광의어를 대표로 쓰지 않는다.** `안전성 평가`의 근거는 `안전성`(df=340)이
  아니라 `안전성 평가`(df=50)다. 전자를 쓰면 표제어의 근거를 오해하게 된다.

## 한국어 처리의 한계

형태소 분석기(kiwipiepy/konlpy) 없이 조사 제거 휴리스틱을 쓴다. 남는 길이가
2자 미만이면 자르지 않아 `합의/논의/협의`는 보존되지만 오절단이 남는다:

- `비동의 성적` → `비동 성적` (표제어에서 `비동의 성적 합성물`로 교정)
- `신뢰도` → `신뢰` (결과적으로 정당한 용어라 무해)

불용어는 두 갈래다. `KO_SOFT`는 **단독일 때만** 제외(복합어의 머리로는 정당 —
`평가`를 통째로 막으면 `위험 평가`·`안전성 평가`까지 죽는다), `KO_HARD`는
어디에 나와도 제외(기능어·지시어).

## 중심성 실험 — 무엇이 작동했나

"최근성만 보지 말고 중심성도 따져 보자"에서 네 가지를 계산했다
(`centrality.py`, `gloss_and_hubs.py`). 결과가 갈렸다.

### 작동하지 않은 것 — 전부 '일반어 탐지기'였다

| 지표 | 최상위에 뭐가 나왔나 |
|---|---|
| `degree` (동시출현 이웃 수) | AI, 문제, 가능성, 있으, 에서, 등을 |
| `topic_entropy` (17개 토픽 분산) | 의사결정, 자원, 생태계, 등에, 있고, 있지, 통한 |
| `pagerank_pmi` (PMI 가중 PageRank) | 문제의식, 국가 전략, 기여, 동기, 점이, 측면, 주로 |

이유: **코퍼스 전체가 이미 AI 안전 문서다.** 그래서 그래프 중심성이 개념
위계가 아니라 국문 논문·기사의 상투적 연결어를 재발견한다. 중심성이
쓸모 있으려면 여러 도메인이 섞인 코퍼스에서 AI 안전 용어가 구별되는
군집을 이뤄야 하는데, 여기서는 그 군집이 곧 전체다.

`topic_entropy`에 걸었던 가설("여러 영역을 관통하면 기초 개념")도 틀렸다.
코퍼스가 말해주는 건 **관통 = 모호함**이다.

세 지표는 **음의 신호로만** 쓸 값어치가 있다. `degree_norm`이 높은데
병기율이 0에 가까우면 일반어다(`위협` 0.79/0.03, `신뢰성` 0.78/0.03).
반대로 둘 다 높으면 핵심 기술어다(`정렬` 0.74/0.26).

### 작동한 것 — 병기율

원문이 `표제어(뜻풀이)` 형태로 쓴 비율. **필자가 "이건 설명이 필요하다"고
이미 판단한 흔적**이라, 용어집 적격성의 가장 직접적인 증거다.
`정렬`이 260건 중 78건에서 병기된다.

두 방향의 뜻이 다르다 — 나눠서 센다.

- `병기` = `표제어(뜻풀이)` → **이 표기가 설명이 필요한 표제어다**
- `괄호안` = `한글 표제어(이 표기)` → **이 표기는 원어·약어다**
  (GPAI 57%, ASR 52%, CoT 41%, XAI 22% — 한글 표제어에 붙는 쪽)

괄호 내용이 실제 뜻풀이인지 검사한다. `첨부파일(hwp)`·`모집(~5.30)` 같은
서식 괄호는 `NOT_GLOSS`로 걸러낸다(정교화 전 `첨부파일`이 병기율 0.96으로
1위였다).

병기율이 찾아낸 누락 표제어 4개를 추가했다: **사고연쇄(CoT)**,
**보정(calibration)**, **LLM 심판(LLM-as-a-Judge)**, **작업 시간 지평**.
`GPAI`·`ASR`·`XAI`는 기존 표제어의 원어로 확인돼 영문 표기를 보강했다.

### 허브 중심성 — 자리를 바꿔서 쓴다

중심성을 **확정된 100개 표제어끼리만** 계산하면(일반어가 그래프에 없으므로)
제 뜻대로 작동한다. `glossary_top100_hubs.csv`.

- 허브: 오용, 오정렬, 인간 감독, 통제 상실, 프롬프트 인젝션, 레드팀, 투명성
- 주변부: 피지컬 AI, 소버린 AI, 초지능, 범용인공지능

다만 **선정용이 아니라 집필 설계용**이다. 낮은 허브 값은 "덜 중요하다"가
아니라 "별개 영역이다"를 뜻한다 — 피지컬 AI·소버린 AI는 쿼터로 일부러
넣은 독립 영역이라 주변부인 게 정상이고, 중심성으로 자르면 쿼터 설계를
되돌리게 된다. 허브 지표는 집필 순서(허브부터)와 상호참조 anchor 선정에 쓴다.

### 한국어 매칭 주의

허브 그래프를 처음 돌렸을 때 `비동의 성적 합성물`·`표현의 자유`의 이웃이
0으로 나왔다. 후보 추출 단계에서 조사를 뗀 표기(`표현 자유`)로 원문
(`표현의 자유`)을 찾았기 때문이다. `surface_re()`가 한글 토큰 사이에
조사 3자까지 허용해 해결했다.

## 정의문

`scripts/definitions.py` 에 표제어별로 넣는다. 키는 `data/glossary_top100.csv` 의
표제어와 정확히 일치해야 하고, `build_json.py` 가 대조해서 빠진 항목과 오타 난
키를 보고한다.

```python
"파인튜닝": {
    "alt": "미세조정",          # 대안적 번역어 — 카드에 `파인튜닝(미세조정)` 로 붙는다
    "one": "이미 학습된 모델을 …",  # 한줄 정의, 볼드로 나간다
    "body": ("문단1 …", "문단2 …"),  # 반드시 두 문단
    "src": "EU AI법 제14조",     # 조문·표준을 특정할 수 있을 때만
},
```

설명의 목적은 **한줄 정의만으로 이해가 안 되는 사람에게 개념을 풀어 주는** 것이다.
사전 항목처럼 깔끔하게 쓰되 친절하게 — 왜 이런 개념이 필요한지, 어떤 구조에서
그런 일이 생기는지, 무엇과 혼동되는지를 구체적인 예와 함께 짚는다.

문단은 역할을 나눈다. 첫 문단은 **개념의 속을 풀어 준다**(왜 이런 일이 생기고 어떤
구조에서 비롯되는지). 둘째 문단은 **한 발 더 들어간다**(인접 개념과의 구별, 실제로
어떤 모습으로 나타나는지, 왜 다루기 어려운지). 뒤쪽에 구별을 두는 이유는 이 분야에서
잘못 읽히는 대부분이 인접 개념의 혼동에서 생기기 때문이다 — 해석가능성과 설명가능성,
오용과 남용, 환각과 기만, GPAI와 AGI 등.

현재 100개 전부 작성됐고 길이는 한줄 정의 21~43자, 문단 178~277자(중위 232자)다.
근거를 표시한 항목은 13개이고, **나머지는 인용문이 아니라 이 용어집을 위해 쓴
설명이다.** 확인할 수 없는 수치·날짜는 쓰지 않고, **코퍼스 통계나 이 저장소에 관한
언급도 정의문에 넣지 않는다** — 용어 자체의 설명만 남긴다.

## 화면 구성

`docs/index.html` 한 장이다. 분류 칩으로 걸러내고, 정렬(분류순·문서 수·최근성·
병기·허브)을 바꾸고, 검색창에 표제어·영문·정의문·용례 제목을 넣어 찾는다.

카드 한 장의 구성은 이렇다.

```
파인튜닝(미세조정)  fine-tuning              [분류 배지]
문서 33 · 기간 7개월 · 최근 91% · 병기 2 · 괄호안 2 · 허브 0.69
코퍼스 표기 · 파인튜닝(33) / fine-tuning(43) / 미세조정(10)
──────────────────────────────────────  (흐린 선)
한줄 정의 (볼드)
설명 문단 1
설명 문단 2
근거 · EU AI법 제14조                      (있는 항목만)
──────────────────────────────────────  (진한 선)
참고 기사 — 코퍼스에서 뽑은 용례 3건
```

정의문이 검색 대상이라 표제어에 없는 말로도 찾힌다 — `보상 해킹`, `과도 거부`,
`C2PA`, `LAWS`, `머신 언러닝` 같은 것들이다.

지면 토큰·내비게이션은 `scripts/ui_common.py` — AI 안전 라이브러리에서 가져왔다.
지면·타이포·구조는 같게 두어 세 사이트가 한 시리즈로 보이게 하고, **헤더 계열색만
갈라 놓았다.** 동향은 퍼플 네이비(`#474284`), 라이브러리는 슬레이트 네이비
(`#3a5270`)를 쓰므로 용어집은 딥 파인 그린(`#2f5951`)에 구리빛 하이라이트
(`#cf8b5e`)를 쓴다.
